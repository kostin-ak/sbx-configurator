# Архитектура

## Назначение

Проект отделяет пользовательскую конфигурацию от механизма сборки и от runtime.
Это позволяет менять структуру YAML и добавлять протоколы, не рискуя рабочим
сервисом на роутере.

## Слои

### 1. Пользовательская конфигурация

Каталог `config` описывает:

- источники подписок;
- transforms;
- selector-шаблоны;
- устройства и группы;
- категории маршрутизации;
- политики устройств;
- rule-set;
- нативные outbounds и endpoints;
- включение/выключение компонентов.

### 2. Загрузчик конфигурации

`sbx/loader.py` проверяет `apiVersion`, `kind`, обязательные поля, включённые
компоненты и `${secret:...}` ссылки.

Загрузчик превращает YAML в проверенные внутренние модели. Это позволяет менять
внешний формат, не переписывая рабочую логику.

### 3. Источники и протоколы

`sbx/sources.py` загружает URL, файлы и кэшированные подписки.

`sbx/links.py` разбирает share links и возвращает нативные sing-box outbounds.
Поддерживаются VLESS, Trojan, VMess, Shadowsocks и служебные `direct://`,
`block://`.

Для расширенных протоколов используется не выдуманный URI, а нативная YAML
структура из `config/protocols.d`.

`sbx/protocols.py` и `protocols/registry.yaml` проверяют, в какой секции должен
находиться объект и какие поля обязательны.

### 4. Transforms

`sbx/transforms.py` выполняет правила в заданном порядке:

- `rename` — регулярная замена текущего тега;
- `exclude` — исключение узла;
- `patch` — рекурсивное слияние параметров;
- `random_patch` — детерминированный выбор вариантов по MD5.

`stop: true` учитывается только после совпавшего `rename`, как в старом
пайплайне.

### 5. Selectors

`sbx/selectors.py` создаёт selectors по итоговым тегам узлов.

Сохранены важные свойства:

- порядок global selectors, затем local;
- regex-фильтры;
- regex-expansion по selector database;
- автоматическая вставка `[Default]` для устройства;
- поведение пустого `tag` с `regex: true`, требуемое текущей конфигурацией.

### 6. Routing

`sbx/routing.py` генерирует route rules в порядке:

1. `pre_rules`;
2. правила устройств и групп;
3. default rules;
4. `post_rules`.

Список IP-адресов группы сортируется для воспроизводимости. Дублирующийся
`🚀 Proxy` catch-all выражен явным `defaults.catch_all: proxy`.

### 7. Assembly

`sbx/assembly.py` собирает JSON-фрагменты по лексикографическому порядку путей.
Поддерживаются комментарии, `__overwrite__`, merge по `tag`, deduplication
списков и `.disable` каталоги.

Старый `config.parts/30-auto-generated` исключается. Новые generated-фрагменты
подставляются на его логическое место.

### 8. SRS

`sbx/srs.py` читает `srs-build.yaml`, собирает элементы правил и вызывает:

```text
sing-box rule-set compile INPUT.json -o OUTPUT.srs
```

Компилятор всегда тот бинарник, для которого собирается конфигурация. Ошибки
компиляции фатальны: старый SRS не маскирует сбой.

### 9. Миграция

`sbx/migrate.py` выполняет изменения схемы sing-box 1.14 и перенаправляет
роутерные пути в локальные каталоги. Исходный snapshot не меняется.

### 10. Валидация и публикация

Проверки:

- дубликаты тегов;
- неизвестные типы;
- пустые selectors;
- неразрешённые outbound/endpoint-ссылки;
- DNS resolver-ссылки;
- rule-set ссылки;
- наличие локальных SRS;
- финальный `sing-box check`.

Только после успешных проверок `sbx/artifact.py` атомарно публикует JSON и
manifest с SHA-256.

## Runtime-профили

### Полный конфиг

Содержит TUN, DNS hijack, текущие устройства, policies и outbounds. На данном
этапе проверяется только локально через `sing-box check`.

### Proxy-only

`sbx/runtime.py` удаляет:

- TUN inbound;
- DNS hijack;
- правила, привязанные к удалённому TUN;
- автозагрузку UI.

Изменяет:

- mixed inbound на `127.0.0.1:7891`;
- Clash API на `127.0.0.1:9091`;
- loopback-маршрут на `direct`.

Удалённые rule-set могут быть заменены пустыми локальными SRS с сохранением
тегов. Это нужно только для offline smoke test; на полный runtime-конфиг не
влияет.

## Релизный слой

- `sbx/pack.py` — создание и проверка `.sbxpack`;
- `sbx/releases.py` — локальная активация версии и rollback;
- `tools/make_release.py` — source-only пакет;
- `tools/audit_release.py` — аудит source pack.

Source pack не содержит секретов, кэшей, бинарников и runtime-state; бинарник
форка скачивается отдельно (`tools/fetch_singbox.py`) и в Git не попадает.
